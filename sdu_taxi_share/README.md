# SDU Taxi Share 🚕

Telegram-бот для студентов SDU (кампус в Каскелене), которые едут **Алматы → SDU** или
**SDU → Алматы** в одно время. Бот собирает группы по 2–4 человека, чтобы они вместе
заказали одно такси и разделили стоимость.

> Бот **сам такси не заказывает**: когда группа собрана, такси через Yandex Go / inDrive
> вызывает организатор (первый участник группы). Оплата внутри бота тоже не проводится:
> бот только считает доли, а участники переводят деньги организатору через Kaspi.

Все тексты бота на казахском языке, они лежат в `texts.py`.

## Возможности

| Функция | Как работает |
|---|---|
| Регистрация `/start` | имя → почта **только @sdu.edu.kz** → 6-значный код на почту (10 минут, 5 попыток, повторная отправка через 60 с) → пол (необязательно) |
| Добавить поездку | направление → район Алматы → сегодня/завтра → время (06:00–22:00, шаг 15 мин) → «только девушки» (вопрос задаётся только девушкам) |
| Подбор | совпадают направление, район и дата, разница во времени ≤ ±15 мин; группа 2–4 человека; выбирается ближайшая по времени группа |
| «Группа собрана» | время, район, имена и @username тех, кто разрешил его показывать. Почта и телефоны не показываются. Первый участник становится организатором |
| Напоминания | за 30 мин одиночке: «попутчик не найден» + «расширить до ±30 мин»; за 15 мин всем участникам группы: «Вы едете? Да / Нет» |
| Отмена | `/my_trips` → «Болдырмау». Остальные участники получают уведомление. Отмена меньше чем за 30 мин до выезда (если в группе были другие) засчитывается как оценка 1 |
| Деление стоимости | через час после выезда организатор вводит сумму, бот делит её поровну; остаток в тенге раздаётся по 1 ₸, начиная с организатора |
| Оплата | участник: «Мен төледім» → организатор: «Растаймын». Через 24 ч без оплаты админ получает уведомление, а должник не может создавать поездки, пока долг не закрыт |
| Оценка | после поездки каждый оценивает попутчиков (1–5) и может оставить жалобу. При рейтинге < 3 после ≥ 3 оценок админ получает уведомление |
| `/profile` | имя, рейтинг, число поездок, пол, переключатель «показывать username» |
| `/my_trips` | активные и прошлые поездки, кнопки отмены, неоплаченные доли |
| `/help`, `/rules` | инструкция и правила безопасности |
| `/delete_me` | удаляет все данные пользователя (события аналитики обезличиваются) |
| Админ | `/stats` (количества + воронка конверсии), `/complaints`, `/ban <id>`, `/unban <id>` |

`<id>` в `/ban` и `/unban` — внутренний id пользователя. Его показывают `/complaints` и
уведомления админу.

## Быстрый старт

### 1. Получить токен у @BotFather

1. Откройте в Telegram [@BotFather](https://t.me/BotFather) и нажмите **Start**.
2. Отправьте команду `/newbot`.
3. Введите отображаемое имя бота, например `SDU Taxi Share`.
4. Введите username бота. Он должен оканчиваться на `bot`, например `sdu_taxi_share_bot`.
5. BotFather пришлёт токен вида `123456789:AAH...`. Это `BOT_TOKEN`. **Никому его не показывайте.**
   Если токен утёк, отзовите его: `/revoke` в BotFather.

Список команд в меню бот выставит сам при запуске.

### 2. Узнать свой Telegram ID (для ADMIN_IDS)

Напишите боту [@userinfobot](https://t.me/userinfobot): он ответит вашим числовым `Id`.

### 3. Установить зависимости

Нужен Python 3.11+.

```bash
cd sdu_taxi_share
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

### 4. Заполнить `.env`

```bash
cp .env.example .env             # Windows: copy .env.example .env
```

Откройте `.env` и заполните:

| Переменная | Что указать |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `ADMIN_IDS` | Telegram ID администраторов через запятую: `111111111,222222222` |
| `SMTP_HOST` | SMTP-сервер, например `smtp.gmail.com` |
| `SMTP_PORT` | `465` (SSL) или `587` (STARTTLS) |
| `SMTP_USER` | логин почтового ящика, с которого уходят коды |
| `SMTP_PASSWORD` | пароль. Для Gmail это **пароль приложения**: Google-аккаунт → Безопасность → двухэтапная аутентификация → «Пароли приложений» |
| `DEV_MODE` | `true`: письма не отправляются, код печатается в консоль (для разработки). В продакшене `false` |
| `SMTP_FROM` | *(необязательно)* адрес отправителя, по умолчанию `SMTP_USER` |
| `DB_PATH` | *(необязательно)* путь к БД, по умолчанию `data/bot.db` |
| `CODE_SECRET` | *(необязательно)* секрет для хэширования кодов, по умолчанию выводится из токена |

Для первого запуска хватит `BOT_TOKEN`, `ADMIN_IDS` и `DEV_MODE=true`: код подтверждения
появится в консоли в строке `[DEV_MODE] Код подтверждения для ...: 123456`.

### 5. Запустить

```bash
python main.py
```

Остановка — `Ctrl+C`. При первом запуске создаются `data/bot.db` (SQLite) и `logs/bot.log`.

### 6. Тесты

```bash
pytest
```

Тесты не обращаются к Telegram и не отправляют письма:

- `tests/test_matching.py` — алгоритм подбора (окно ±15/±30, район, дата, направление,
  размер группы, «только девушки», выбор лучшей группы);
- `tests/test_payments.py` — деление суммы (ровное, с остатком, сохранение суммы);
- `tests/test_flow.py` — подбор, выход из группы, расширение окна, долги, воронка, `/delete_me` на SQLite в памяти;
- `tests/test_email_codes.py` — домен почты, хэширование кода, лимит попыток;
- `tests/test_bot_e2e.py` — сквозные сценарии через Dispatcher с фейковой сессией Telegram.

## Структура проекта

```
sdu_taxi_share/
├── main.py              # точка входа: логирование, БД, роутеры, планировщик, polling
├── config.py            # .env + константы (районы, окно подбора, лимиты и т.д.)
├── texts.py             # все тексты (kk); TEXTS["ru"] можно добавить позже
├── db/
│   ├── schema.sql       # таблицы users, trips, groups, payments, ratings, email_codes, events
│   ├── database.py      # подключение aiosqlite и создание схемы
│   └── repo.py          # все SQL-запросы
├── services/
│   ├── matching.py      # алгоритм подбора (чистые функции) + вход/выход из групп
│   ├── payments.py      # деление суммы, долги, подтверждение оплаты
│   ├── ratings.py       # средний рейтинг, порог для уведомления админа
│   ├── email_codes.py   # коды подтверждения (HMAC-хэш), SMTP / DEV_MODE
│   ├── analytics.py     # события эксперимента и воронка
│   ├── notify.py        # отправка уведомлений, общие сценарии (выход из группы и т.п.)
│   ├── scheduler.py     # APScheduler: напоминания, запрос суммы, просрочки
│   └── timeutil.py      # время Алматы, слоты 06:00–22:00
├── handlers/            # start (регистрация, /help, /rules, /delete_me), trips, payments,
│                        # ratings, profile, admin, fallback, middlewares
├── keyboards/           # reply- и inline-клавиатуры, фабрики callback_data
└── tests/
```

Районы Алматы задаются в `config.py` (`DISTRICTS`), там же все числовые параметры
(окно подбора, размер группы, сроки напоминаний и оплаты).

### Как добавить русский язык

Добавьте в `texts.py` словарь `TEXTS["ru"]` с теми же ключами, что у `TEXTS["kk"]`, и
передавайте `lang="ru"` в `t()`. Ключи, которых нет в `ru`, берутся из `kk`.

## Приватность и логирование

- Хранится минимум данных: имя, университетская почта, Telegram ID и username,
  пол (необязательно). Телефоны не запрашиваются.
- Почта нигде не показывается другим пользователям и администраторам.
- Коды подтверждения хранятся только как HMAC-SHA256-хэш и удаляются после проверки.
- `@username` в группе показывается только тем, кто это разрешил (`/profile`).
- `/delete_me` удаляет пользователя, его поездки, платежи и код подтверждения. Текст его
  жалоб стирается. События аналитики остаются только обезличенными: `user_id` заменяется
  отрицательным числом, не связанным ни с одной записью.
- `logs/bot.log` (ротация 5 × 2 МБ) содержит только внутренние id и типы событий, без
  имён, почты и username.

## Аналитика эксперимента

В таблицу `events` пишутся события `registered`, `trip_created`, `group_formed`,
`trip_completed`, `payment_confirmed`. `/stats` показывает:

- число пользователей, заявок на поездки, собранных групп, состоявшихся поездок и подтверждённых оплат;
- воронку по уникальным пользователям: **зарегистрировались → создали поездку →
  попали в собранную группу → поездка состоялась**, с конверсией от предыдущего шага и от первого.

Поездка считается состоявшейся, когда организатор ввёл сумму.

## Ограничения MVP

- Состояния диалогов (FSM) хранятся в памяти: после перезапуска незавершённый ввод
  (например, регистрацию) нужно начать заново. Сами данные хранятся в SQLite.
- Не реализованы, по ТЗ: оплата внутри бота, автоматический вызов такси, работа с водителями,
  мобильное приложение, веб-панель.
- Группа, организатор которой не ответил на запрос суммы в течение суток, закрывается
  автоматически и не считается состоявшейся.
